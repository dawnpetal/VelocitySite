Tutorial 04

Multi-Instance

Target specific Roblox accounts and send scripts to one, several, or all of them at once, without re-pasting or switching windows.

01

How it works

Every account in the dropdown has a coloured dot. That dot is all you need to read before sending a script.

Green - Active
In-game right now, reporting back to VelocityUI. Scripts sent here go through.
Yellow - Stale
Seen before, not active right now. Could be offline, not in a game, or executor has not reported in. Scripts will not reach this account.
Monitor icon + Instances dropdown - top-right corner of the UI
Click the monitor icon to activate it first, then click the dropdown arrow beside it. These are two separate controls. Clicking the monitor icon again will not close the dropdown.
02

First-time setup

VelocityUI writes a script to your executor's autoexecute folder on first boot. That script is what registers each account with the UI when Roblox launches. Until that file exists, nothing appears in the dropdown.

First time using VelocityUI? Open VelocityUI before launching Roblox. The file gets written on boot. If Roblox opens first, the executor runs before the file exists and nothing registers.

Do this once, in this order:

01
Open VelocityUI and let it fully load.
02
Launch Roblox and join a game on your first account.
03
Repeat for each additional account. Each one appears in the dropdown as it joins.
Used VelocityUI before? The file is already in your executor folder. Your executor runs it automatically on every Roblox launch. Launch order no longer matters.
03

Targeting instances

Click the monitor icon, then open the Instances dropdown. Each account is listed by username with its status dot. Click any account to toggle it as a target.

Select one or many
Selection persists
Accounts are independent
Nothing selected means the script runs on the default active instance, same as normal execution without multi-instance.
04

Running the script

Select your targets, then hit run or press Cmd Return as normal. VelocityUI sends to all selected instances at the same time, no delays.

If one account fails (lost injection, still loading), the rest are unaffected. Each instance is handled separately.
05

Edge cases

Something not working? Find it below.

Account not showing up at all
Almost always means Roblox launched before VelocityUI on the first ever use, so the autoexecute file was not there yet. Close Roblox, open VelocityUI first, then relaunch.
Account went yellow mid-session
The Roblox process closed or crashed. Re-join on that account and the executor's autoexecute script re-registers it once the game loads. The dot goes green again on its own.
Script ran on the wrong account
A previous selection was still active. Open the dropdown and check which accounts are highlighted. Deselect anything you do not want before running. Selection persists between executions.
Updated VelocityUI, now no instances show
Every boot, VelocityUI checks the autoexecute file and reads the version number at the top. Any mismatch and it replaces the file. If Roblox launched before VelocityUI ran that check, the executor ran the old file first. Fix: close Roblox, open VelocityUI so it rewrites the file, then relaunch Roblox. Sorted until the next update.
Accounts must be fully loaded into a game. Accounts on the loading screen or mid-teleport will not receive scripts reliably.
